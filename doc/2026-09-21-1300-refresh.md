## 1. Idea summary

## 2. MVP scope

- Problem: missing or stale IPO schedules and results must not reach the app.
- Must-have: fresh three-provider calendar ledger; primary-source checks; compare all September/October candidates with canonical inputs, stock details and feeds; regenerate needed outputs; JSON/monthly/schedule validation and Dart analysis.
- Out of scope: app release, UI, new automation, speculative values, zero placeholders and unrelated identifier edits.
- Success: publish only evidence-backed material changes after every required gate passes; otherwise preserve current public data and record the blocker. Quiet when no material changes or new actionable failure.
- Monetization: existing app advertising unchanged; no runtime service or tracking added.

## 3. Feature specification

- Discovery: exact company plus subscription window, official issuer/broker/filing when available; classify aliases, rights offerings and non-equity subscriptions explicitly.
- Metrics: source dates and quantity-basis lockup preserved, percentages stored as fractions. No forecast, inferred or unpublished values. Do not turn an intraday listing price into a final close or final return.
- State: modify reviewed source inputs only, generate locally without remote discovery on copies if required, preserve all unrelated changes.
- Errors: unresolved identities and any audit ERROR prohibit commit/push. Source outages are limitations, not evidence of zero or a changed value.
- Acceptance: all applicable validators and Dart analysis pass; main SHA and exact stock/feed Raw URLs verified if publication is needed.

## 4. Wireframe / data flow

```text
KST clock -> current + next-month public calendars -> candidate ledger
 -> primary source + canonical input/output comparison
 -> reviewed inputs -> deterministic feeds -> validation gates
 -> scoped main push + remote checks OR unchanged/blocked report
```
